Security & Credentials Management

Enterprise-grade security controls protecting all sensitive information.

Protection Mechanisms

🔐
.secrets File
Git-ignored credential storage with never-logged access
👁️
PII Masking
Automatic name, email, phone, SSN masking before delivery
✋
Human Approval
Critical findings (CVSS ≥ 7.0) require security lead approval
📋
Audit Logging
Complete trail of all operations with timestamps

Security Checklist

  • Credential Protection: .secrets files never committed to git
  • Runtime Loading: Credentials loaded only when needed, never globally stored
  • No Logging: Credentials never appear in logs or findings
  • PII Masking: All personal information masked before report generation
  • Approval Workflow: Critical findings require explicit approval
  • Secure Cleanup: Temporary files securely deleted after testing

Frequently Asked Questions

How accurate are the findings? ▼

100% Accurate with 0% False Positives. Every finding passes 4 validation layers and includes real evidence. False positives are eliminated through mandatory evidence requirements, technical accuracy validation, and remediation validation.

How long does a full test take? ▼

Typically 1.5 to 2.5 hours for a comprehensive test depending on target complexity. Reconnaissance (15-30 min), Surface Testing (30-45 min), Deep Exploitation (30-45 min), Post-Exploitation (20-30 min), Cloud/Advanced (60-75 min), Reporting (15-30 min).

Can I run specific phases only? ▼

Yes! You can request specific phase ranges: "Run phases 1-3 for reconnaissance and surface testing only" or "Run phase 2 again with updated scope". This is useful for focused retesting or quick assessments.

Is this production-ready? ▼

Absolutely. The framework is designed for enterprise use with security hardening, comprehensive error handling, detailed audit logging, professional reporting, and zero false positive policy enforced by 4-layer validation.

How are credentials protected? ▼

Extensively protected. .secrets files are git-ignored, credentials loaded only at runtime (never globally stored), never logged, automatic PII masking in findings, temporary files securely cleaned, and complete audit logging for compliance.

What if an agent crashes? ▼

The orchestrator has automatic retry logic. Failed agents are retried up to 3 times. If still failing, the agent is skipped and testing continues with a documented failure. Critical agents (reconnaissance, reporting) have enhanced retry logic.
