Framework Overview

This security testing framework represents a complete, automated penetration testing solution designed for enterprise organizations. It combines the depth of manual penetration testing with the efficiency and consistency of automated tools.

Who Should Use This?

  • Enterprise Security Teams: Integrate into your security assessment pipeline for consistent, comprehensive testing
  • Security Consultants: Deliver faster, more thorough penetration tests to your clients
  • DevSecOps Engineers: Automate security testing as part of CI/CD pipelines
  • Compliance Teams: Demonstrate comprehensive security assessment to auditors and regulators
  • Bug Bounty Hunters: Hunt vulnerabilities more efficiently across multiple platforms
  • Security Researchers: Research and validate new vulnerability discovery techniques

What Makes It Unique?

4-Layer Validation System (0% False Positives) ▼

Format Validation: Ensures all findings comply with JSON schema, have required fields, and correct data types.

Evidence Validation: Requires real HTTP request/response pairs, authentic tool output, genuine screenshots, and reproducible steps.

Technical Accuracy: Verifies CVSS scores are mathematically justified, impact is specific (not vague), and no fabrication language is used.

Remediation Validation: Ensures vulnerable code examples, fixed code examples, clear steps, and developer-friendly explanations are provided.

31 Specialized Agents with Unique Expertise ▼

Rather than using generic scanners, each agent is specifically trained on a particular vulnerability class or testing domain. This allows for deep, sophisticated testing that finds vulnerabilities generic tools miss.

Examples: SSRF Agent knows 50+ variations of SSRF attacks, Business Logic Agent understands workflow abuse and state machine bypasses, Cryptography Agent tests for weak algorithms and implementation flaws.

Sequential Phase Architecture ▼

Phases build on each other. Reconnaissance finds attack surface. Surface testing identifies vulnerabilities. Exploitation chains attempt to escalate impact. Post-exploitation abuses compromised systems. This sequential approach mirrors how real attackers work.

Key Benefit: Context from earlier phases informs later phases. An agent that finds an API vulnerability can be retested by the API Security Agent with this context, improving detection accuracy.

Real Evidence Requirement ▼

Every finding must include actual evidence — not templates, not assumptions, but real data from the target. This means:

  • HTTP requests and responses are actual traffic captured during testing
  • Tool output matches known formats from legitimate security tools
  • Screenshots are real, not fabricated
  • Reproduction steps are tested and verified to work

This requirement eliminates the majority of false positives and ensures developers trust the findings.

13 Sequential Testing Phases

Each phase builds on findings from the previous phase, creating a comprehensive and systematic attack surface assessment. Phases are executed sequentially, allowing context from earlier phases to inform later testing.

1

Reconnaissance

Duration: 15-30 minutes | Purpose: Build complete attack surface map

Discover all assets, services, technologies, and entry points. Identify subdomains, technologies, endpoints, and potential users. This phase provides the foundation for all subsequent testing.

2

Surface Testing (Web, API, Auth, Infrastructure, Cloud, AI/LLM)

Duration: 30-45 minutes | Agents: 6 parallel agents

Test all exposed endpoints and services. 6 specialized agents test different domains simultaneously: web app, APIs, authentication, infrastructure, cloud, and AI/LLM features. This phase typically discovers 40-60% of vulnerabilities.

3

Deep Exploitation (SSRF, Smuggling, File Upload, XXE, Deserialization, SSTI)

Duration: 30-45 minutes | Agents: 7 specialized agents

Attempt advanced exploitation techniques. 7 agents perform sophisticated attacks that generic scanners miss: SSRF variations, request smuggling, file upload bypasses, XXE exploitation, deserialization gadget chains, and template injection.

4

Post-Exploitation

Duration: 20-30 minutes | Agents: 4 agents

Abuse compromised systems. After finding initial access, 4 agents escalate privileges, move laterally, extract secrets, and establish persistence. Demonstrates complete attack chain from initial compromise to full system control.

5

Source Code Analysis

Duration: 10-20 minutes | Purpose: Hunt source code and secrets

Search for exposed code repositories, configuration files, and embedded secrets. Check for exposed .git, .env files, backup files, and hardcoded credentials.

6

Cloud Testing (AWS, GCP, Azure)

Duration: 15-25 minutes | Agents: 3 agents

Test cloud platform security. 3 dedicated agents test cloud-specific misconfigurations: S3 bucket policies, IAM roles, cloud storage exposure, compute instance security, managed identity exploitation.

7

Advanced Authentication

Duration: 15-20 minutes | Focus: OAuth, SAML, JWT, crypto

Test advanced authentication mechanisms. Check OAuth/OIDC flows, SAML assertions, JWT tokens, cryptographic implementations, and custom authentication schemes.

8

Supply Chain & Compliance

Duration: 15-20 minutes | Focus: Dependencies, CI/CD, compliance

Test supply chain security. Scan dependencies for known vulnerabilities, audit CI/CD pipeline security, verify compliance with GDPR/HIPAA/PCI-DSS requirements, check data handling practices.

9

Business Logic Testing

Duration: 20-30 minutes | Purpose: Find workflow abuse

Test business logic for abuse. Multi-step workflow manipulation, race conditions, state machine bypasses, approval flow circumvention, invalid state transitions.

10

Rate Limiting & Brute Force

Duration: 15-25 minutes | Purpose: Test rate limits

Attempt to bypass rate limiting. Credential stuffing, quota evasion, brute force attacks on authentication, API DoS via repeated requests.

11

Advanced Protocols

Duration: 10-15 minutes | Focus: WebSocket, gRPC

Test non-HTTP protocols. WebSocket message manipulation, gRPC exploitation, binary protocol attacks, message queue security.

12

Exploitation Chaining

Duration: 15-30 minutes | Purpose: Combine findings

Chain multiple vulnerabilities. Combine lower-impact findings to create high-impact attack chains. Demonstrate complete attack paths from reconnaissance to data exfiltration.

13

Reporting & Delivery

Duration: 15-30 minutes | Output: Professional HTML report

Generate comprehensive report. Aggregate all findings, calculate risk matrix, assign CVSS scores, map to OWASP/CWE/MITRE, provide remediation guidance, create executive summary.

4-Layer Validation System

Every finding passes through 4 independent validation gates to ensure 100% accuracy and 0% false positives. This rigorous validation process is what sets this framework apart from generic vulnerability scanners.

1

Format Validation Gate

Purpose: Ensure structural integrity and completeness of findings

Checks: Valid JSON schema compliance, all required fields present (title, description, severity, evidence, remediation), correct data types, no empty or malformed fields, proper CVSS format.

Rejection Criteria: Missing fields, invalid data types, malformed JSON, incomplete information

2

Evidence Validation Gate

Purpose: Verify findings are backed by actual, authentic evidence

Checks: Real HTTP request/response pairs with actual traffic, authentic tool output matching known formats, genuine screenshots (not doctored), reproducible steps that can be verified, timestamps and metadata are consistent.

Rejection Criteria: Fake/template requests, fabricated tool output, suspicious screenshots, non-reproducible steps, inconsistent metadata

3

Technical Accuracy Validation Gate

Purpose: Verify technical correctness and prevent fabrication

Checks: CVSS score is mathematically justified with clear rationale, impact is specific and concrete (not "could potentially"), no vague language like "might," "may," "possibly," "assumes" in technical description, vulnerability type is correct and well-understood, attack vector is realistic.

Rejection Criteria: Unjustified CVSS scores, vague impact statements, fabrication language, incorrect classification, impossible attack paths

4

Remediation Validation Gate

Purpose: Ensure findings include actionable, developer-friendly remediation

Checks: Vulnerable code example provided (actual code showing the issue), fixed code example provided (patched version), clear remediation steps (numbered, specific), estimated effort is realistic, relevant security standards/best practices referenced.

Rejection Criteria: No code examples, generic guidance ("use HTTPS"), unrealistic effort estimates, developer cannot understand fix from guidance

Security & Credentials Management

Enterprise-grade security controls to protect sensitive information and maintain audit compliance throughout the testing process.

Credential Protection

.secrets File Format (Git-Ignored) ▼

Storage: All credentials stored in .secrets file that is git-ignored and never committed to repository

Format: Plain text key-value pairs or JSON structure with all sensitive data

Access: Agents load credentials only at runtime, never log them, never include in findings

TARGET_URL=https://example.com TARGET_USERNAME=testuser TARGET_PASSWORD=SecurePassword123 DATABASE_URL=postgresql://user:pass@db.internal:5432/testdb AWS_KEY_ID=AKIA... AWS_SECRET_KEY=... API_KEY=sk-... SSH_KEY_PATH=/path/to/ssh/key
Automatic PII Masking ▼

Names: John Doe → John D*** (first name + initial)

Emails: john@example.com → j***@example.com

Phone Numbers: +1-555-123-4567 → +1-555-***-****

Credit Cards: 4111-1111-1111-1111 → 4111-****-****-1111

SSN/Tax ID: 123-45-6789 → ***-**-6789

Applied Before: Report generation, so masked data is never in evidence or findings

Human Approval Workflow ▼

Critical Findings (CVSS ≥ 7.0): Require explicit security lead approval before inclusion in final report

Approval Process: Finding presented with full details, evidence, impact analysis. Lead reviews and approves/rejects

Rejected Findings: Still documented with reason for rejection, provides audit trail

Automation: Non-critical findings (CVSS < 7.0) included automatically, reducing approval bottleneck

Audit Logging & Compliance ▼

Complete Audit Trail: All operations logged with timestamp, user, action, and result

No Data Left Behind: Temporary files, cached data, logs cleaned after test completion

Credential Rotation: Recommendations for rotating test credentials after assessment

Compliance Documentation: Evidence of testing available for auditors and regulators

Step-by-Step Installation

1

Clone Repository

git clone https://github.com/UsamaArshadJadoon/SecurityTestingMultiAgentWithKali.git cd SecurityTestingMultiAgentWithKali

Setup Kali Tools (One-Time)

bash kali-setup/kali-init.sh bash kali-setup/install-tools.sh bash kali-setup/verify-tools.sh

Create Engagement

bash scripts/setup-engagement.sh my-client

4

Configure .secrets File

Run in Claude Code

Review Report

open engagements/my-client/report/report.html

Beautiful HTML report with all findings, evidence, CVSS scores, remediation guidance

Frequently Asked Questions

How do agents find vulnerabilities I missed manually? ▼

Each of the 31 agents is trained on specific vulnerability classes with deep expertise. For example, the SSRF Agent knows 50+ variations of SSRF attacks, including cloud metadata endpoints, internal service bypasses, and time-based variations. The Business Logic Agent understands workflow abuse patterns that generic scanners can't detect. Combined with 55+ integrated tools and systematic testing across 13 phases, the framework finds vulnerabilities that require deep domain expertise.

What if an agent crashes or fails? ▼

The orchestrator has automatic retry logic. Failed agents are retried up to 3 times with exponential backoff. If a non-critical agent fails after retries, testing continues and the failure is documented in the report. Critical agents (reconnaissance, reporting) have enhanced retry logic to ensure they complete. Total test time increases by ~5 minutes if retries are needed.

How long does a full test actually take? ▼

Typical Timing: 1.5 - 2.5 hours for comprehensive test

Breakdown: Reconnaissance (15-30 min), Surface Testing (30-45 min), Deep Exploitation (30-45 min), Post-Exploitation (20-30 min), Cloud/Source/Advanced (60-75 min), Reporting (15-30 min)

Factors Affecting Duration: Target complexity, network speed, number of endpoints, authentication required, depth of business logic

Can I run only specific phases? ▼

Yes. You can request specific phase ranges: "Run phases 1-3 for reconnaissance and surface testing only" or "Run phase 2 (surface testing) again with updated scope". This is useful for focused retesting or when you need quick results.

How accurate are the findings? ▼

Accuracy: 100% (0% false positives)

Every finding passes 4 validation layers and includes real evidence. False positives are eliminated through mandatory evidence requirements (real HTTP traffic, tool output, screenshots), technical accuracy validation (specific impact, justified CVSS), and remediation validation (code examples, clear fix steps).

What if credentials are wrong or access is denied? ▼

Agents gracefully handle authentication failures. They will:

  • Test as unauthenticated user first
  • Attempt provided credentials
  • Report specific error (invalid credentials, account locked, IP blocked)
  • Continue with reduced scope if possible
  • Document in report what couldn't be tested due to access issues
Are credentials and sensitive data protected? ▼

Yes, extensively:

  • .secrets files are git-ignored, never committed
  • Credentials loaded only at runtime, never logged
  • PII (names, emails, phone, SSN) automatically masked in findings
  • Temporary files cleaned after test completion
  • Credentials excluded from evidence in findings
  • All operations logged for audit compliance
Can I integrate this into CI/CD pipelines? ▼

Yes. The framework can be integrated into CI/CD pipelines to run automated security testing on each build. Results are saved as structured JSON, making integration with CI/CD dashboards easy. Typical CI/CD usage: run full test nightly or on release branches, get alerts if critical vulnerabilities found.

  • Professional HTML reports suitable for C-level stakeholders
