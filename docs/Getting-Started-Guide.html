📋 Before you start — what you need

A computer Windows, macOS, or Linux (your "control" machine)
Kali Linux A VM or machine with the security tools (the "toolbox")
Claude Code Installed and signed in (easiest way to run)
Node.js 14+ Runs the orchestrator engine
Python 3.8+ Used by some tools
Authorization Written permission to test the target — required
Only test what you own or are authorized to testRunning these tools against systems without explicit written permission is illegal. The framework enforces a scope/authorization gate (Step 8) and will refuse to run without it.
1

Check your computer has the basics

What this does: confirms Node, Python, and Git are installed before anything else.

Command
node --version
python3 --version
git --version
Expected output (versions may differ)v18.19.0 Python 3.11.6 git version 2.43.0
If a command says "not found"Install the missing tool: nodejs.org (Node), python.org (Python), git-scm.com (Git). On Windows, the win Git Bash terminal that ships with Git is a good place to run these commands.
2

Download the framework

What this does: copies the project to your computer and moves you into its folder.

Command
git clone https://github.com/UsamaArshadJadoon/SecurityTestingMultiAgentWithKali.git
cd SecurityTestingMultiAgentWithKali
Expected outputCloning into 'SecurityTestingMultiAgentWithKali'... done.
Stay in this folderRun every command from Step 3 onward inside the SecurityTestingMultiAgentWithKali folder.
3

Set up your Kali toolbox

What this does: installs the 150+ security tools on your Kali machine. Run these on the Kali machine (or via SSH). The install step takes ~20–30 minutes.

Commands (run on Kali)
bash kali-setup/kali-init.sh        # one-time base setup
bash kali-setup/install-tools.sh    # installs 150+ tools (~20-30 min)
bash kali-setup/verify-tools.sh     # confirms tools are installed
Expected output (end of verify)✅ nmap - installed ✅ sqlmap - installed 📊 Results: 7 found, 0 missing ✅ All required tools are installed!
4

Connect your computer to Kali over SSH

What this does: lets the framework send tool commands to Kali securely. You set it up once.

4a · On the Kali machine — turn on SSH
sudo systemctl enable --now ssh
ip addr | grep inet          # find Kali's IP, e.g. 192.168.56.101
4b · On your computer — create a key and copy it to Kali
ssh-keygen -t ed25519 -f ~/.ssh/kali_key -N ""
ssh-copy-id -i ~/.ssh/kali_key.pub kali@192.168.56.101
ssh -i ~/.ssh/kali_key kali@192.168.56.101 "echo connected"
Expected outputconnected
4c · Tell the framework how to reach Kali
export KALI_HOST=192.168.56.101   # your Kali IP
export KALI_USER=kali
export KALI_KEY=~/.ssh/kali_key
Sample values192.168.56.101 is an example Kali IP and kali is the default username — replace them with yours from step 4a. On win Windows PowerShell use $env:KALI_HOST="192.168.56.101" instead of export.
5

Health-check Kali

What this does: confirms your computer can reach Kali and that the essential tools respond — before you run a real test.

Command
bash orchestrator/kali-health-check.sh
Expected output🔍 Kali health check SSH connectivity... ✅ nmap... ✅ sqlmap... ✅ nuclei... ✅ ✅ Kali is ready.
If SSH fails hereRecheck Step 4 — the IP in KALI_HOST, the username, and that ssh ... "echo connected" worked.
6

Create an engagement (your project)

What this does: makes a folder for one target with starter config, scope, and a credentials template.

Command · sample name "acme-corp"
bash scripts/setup-engagement.sh acme-corp
Expected output🔧 Setting up engagement: acme-corp ✅ Engagement setup complete! Creates: engagements/acme-corp/config.yaml, scope.md, .secrets.template
Pick any nameUse something short with no spaces, e.g. acme-corp, my-app, client01. Use the same name in every step after this.
7

Add your target & credentials

What this does: tells the framework the target URL and any test logins. This file is git-ignored — it never gets committed.

Commands
cp engagements/acme-corp/.secrets.template engagements/acme-corp/.secrets
nano engagements/acme-corp/.secrets
Fill it in (sample values)
TARGET_URL=https://staging.acme-corp.com
TARGET_DOMAIN=acme-corp.com
TARGET_USERNAME=testuser@acme-corp.com
TARGET_PASSWORD=Sup3rSecret!
AUTHORIZATION_NAME=Jane Doe (Security Lead)
AUTHORIZATION_EMAIL=jane@acme-corp.com
nano basicsAfter editing, press Ctrl+O then Enter to save, and Ctrl+X to exit. Prefer another editor? Any text editor works.
8

Confirm scope & authorization (safety gate)

What this does: defines exactly what is in-scope and records that testing is authorized. The orchestrator will not start without this.

Command
nano engagements/acme-corp/scope.md
Required — add this exact line to scope.mdThe engine checks scope.md for the literal line below and refuses to run if it is missing:
authorization.confirmed: true
Sample scope.md content
# Engagement Scope

authorization.confirmed: true

## Target
- URL: https://staging.acme-corp.com

## In Scope
- Web application and its APIs

## Out of Scope
- Production database, third-party payment services

## Restrictions
- No DoS attacks; testing during business hours only
9

Validate everything is ready

What this does: checks that config.yaml, scope.md, and .secrets all exist and look valid — catches mistakes before the run.

Command
bash scripts/validate-config.sh acme-corp
Expected output🔍 Validating engagement configuration: acme-corp ✅ Found: config.yaml ✅ Found: scope.md ✅ Found: .secrets ✅ Configuration validation complete! 📋 Ready to run: node orchestrator/Orchestrator.js acme-corp
If it reports something missingGo back to the step for that file (7 for .secrets, 8 for scope.md) and re-run this command until it is all ✅.
10

Run the penetration test

What this does: starts the orchestrator — it runs the phases, dispatches the agents, validates every finding, and builds the report. Pick whichever way is easier for you.

Option A · Easiest — in Claude Code

Open the project folder in Claude Code and simply type:

Run full penetration test for acme-corp
Option B · Terminal
bash scripts/run-pentest.sh acme-corp
# or run the engine directly:
node orchestrator/Orchestrator.js acme-corp
Expected output (start)🚀 Starting penetration test for: acme-corp ✅ Scope gate passed ✅ Evidence directories ready ║ 86 Agents | 30 Phases | Claude Code Agent Dispatch ║
Critical findings pause for youAnything high-severity (CVSS ≥ 7.0) waits for a human sign-off before it is finalized — that is expected behavior.
11

Check progress

What this does: shows how far the run has got — completed phases, agents, findings so far. Safe to run any time in another terminal.

Command
bash scripts/check-status.sh acme-corp
Expected output📊 Status for engagement: acme-corp Completed phases: 8 Completed agents: 22/86 Findings so far : 31 Last update : 2026-07-30T12:14:00Z
12

Open your report

What this does: opens the finished HTML report — findings, severity, evidence, CVSS scores, and code fixes.

Command (pick your OS)
# macOS
open engagements/acme-corp/report/report.html
# Windows
start engagements/acme-corp/report/report.html
# Linux
xdg-open engagements/acme-corp/report/report.html
You getA professional report: executive summary, risk matrix, each finding with evidence + reproducible steps, CVSS 3.1 score, OWASP/CWE/MITRE mapping, and vulnerable-vs-fixed code. PII is masked automatically.
That's it! 🎉You've run a full test. To test another target, repeat from Step 6 with a new engagement name.
