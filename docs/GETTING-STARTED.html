✨Overview & Features

What is this Framework?

A complete, automated penetration testing framework that orchestrates 31 specialized security agents across 13 sequential testing phases. Each agent performs deep security testing using 55+ integrated Kali Linux tools, ensuring 100% accuracy with real evidence and zero false positives.

Sequential testing from reconnaissance to reporting

100% accuracy with zero false positives

Critical findings require human sign-off

⚙️Installation Guide

Prerequisites

  • Windows 11 with Hyper-V enabled
  • Kali Linux VM running (accessible via SSH)
  • Claude Code installed and configured
  • Git installed on your system
  • At least 8GB RAM available

Step 1: Clone Repository

1

Open your terminal and clone the repository:

git clone https://github.com/UsamaArshadJadoon/SecurityTestingMultiAgentWithKali.git
cd SecurityTestingMultiAgentWithKali

Step 2: Verify Git Configuration

2

Make sure the repository is properly initialized:

git status
✓ You should see the main branch and uncommitted files

Step 3: Setup Kali Tools (One-Time)

3

This installs 55+ penetration testing tools on your Kali VM:

bash kali-setup/kali-init.sh
bash kali-setup/install-tools.sh
ℹ️ This may take 20-30 minutes. Grab a coffee!

Step 4: Verify Installation

4

Verify all tools installed correctly:

bash kali-setup/verify-tools.sh
✓ You should see "All tools verified successfully"

Step 5: Verify Kali Connectivity

5

Test SSH connection to Kali VM:

bash scripts/test-kali-connection.sh
✓ Should show "Kali VM Connected Successfully"

🔧Setup & Configuration

Create New Engagement

1

Create a new engagement directory:

bash scripts/setup-engagement.sh my-client

This creates:

engagements/my-client/ ├── config.yaml # Configuration ├── scope.md # Scope & authorization ├── .secrets # Credentials (YOU FILL IN) ├── .env # Environment variables └── .gitignore # Ignores secrets

Add Credentials

2

Edit the .secrets file with test credentials:

nano engagements/my-client/.secrets

Add these credentials (use TEST accounts only):

# Primary Target TARGET_URL="https://app.my-client.com" # Admin Account (for testing) ADMIN_USERNAME="admin_test_001" ADMIN_PASSWORD="TempAdmin123!@#" # Regular User Account USER_USERNAME="user_test_001" USER_PASSWORD="TempUser123!@#" # Database Access (if allowed) DB_HOST="db.internal.my-client.com" DB_USER="test_user" DB_PASSWORD="TempDB123!@#"
⚠️ Important: Use TEMPORARY test accounts, NOT production credentials

Configure Scope

3

Edit scope.md with authorization details:

nano engagements/my-client/scope.md

Include:

  • Authorized target URLs
  • IP ranges in scope
  • Systems explicitly excluded
  • Testing period / hours
  • Authorization letter / approval

Update Configuration

4

Edit config.yaml with engagement details:

nano engagements/my-client/config.yaml

Configure:

engagement: name: "my-client" date_started: "2026-07-29" target_url: "https://app.my-client.com" scope: "Internal + External" security: kali_vm: "192.168.1.100" kali_ssh_port: 22 verify_ssl: true

Validate Configuration

5

Verify everything is configured correctly:

bash scripts/validate-config.sh my-client
✓ You should see "Configuration validated successfully"

⭐Best Practices

1. Use Test Accounts Only

Never use production credentials! Always use dedicated test accounts for penetration testing. They should be easily identifiable as test accounts (e.g., test_user_001).

2. Clear Scope & Authorization

  • Have written authorization before testing
  • Clearly define in-scope systems
  • Document excluded systems
  • Specify testing window (dates/hours)
  • Contact info for emergencies

3. Run Tests During Off-Hours

Schedule penetration tests when:

  • Production traffic is minimal
  • Support team is available (if needed)
  • Database backups are complete
  • Systems are not in critical operation

4. Monitor System Impact

  • Watch for alerts/alarms during testing
  • Monitor CPU/memory usage
  • Check for performance degradation
  • Have quick kill-switch (stop test) ready

5. Secure Your Credentials File

IMPORTANT: The .secrets file is git-ignored and never committed. However:
  • Never commit .secrets to version control
  • Keep .secrets file secure on your machine
  • Delete .secrets after engagement is complete
  • Use strong temporary passwords

6. Review Findings Carefully

  • Check findings for false positives before reporting
  • Verify all evidence is real and authentic
  • Ensure reproduction steps are accurate
  • Review remediation advice is correct

7. Handle Critical Findings

For findings with CVSS ≥ 7.0 (Critical/High):

  • Review thoroughly before reporting
  • Ensure evidence is 100% authentic
  • Test reproduction steps multiple times
  • Get security team sign-off
  • Notify client immediately if exploitable

8. Document Your Testing

  • Keep testing logs and timestamps
  • Document any issues encountered
  • Note any out-of-scope activities
  • Create timeline of testing phases

🔧Troubleshooting

Kali VM Connection Issues

Problem: "Kali VM not responding" error

Solutions:

  • Verify Kali VM is running in Hyper-V
  • Check SSH is enabled: sudo systemctl status ssh
  • Verify network connectivity: ping kali.local
  • Check firewall isn't blocking SSH (port 22)
  • Restart SSH service: sudo systemctl restart ssh

Tool Installation Failed

Problem: Tools not installing correctly

Solutions:

  • Run installation with elevated privileges: sudo bash install-tools.sh
  • Update package manager first: sudo apt update && sudo apt upgrade
  • Check internet connectivity on Kali VM
  • Run verification: bash verify-tools.sh
  • Check disk space: df -h (need at least 10GB)

Credentials Not Loading

Problem: "Credentials missing" error

Solutions:

  • Verify .secrets file exists: ls -la engagements/my-client/.secrets
  • Check file format is correct (not .secrets.txt)
  • Ensure .secrets is in correct directory
  • Verify file is readable: chmod 600 .secrets
  • Test credentials loading: bash scripts/test-credentials.sh my-client

Test is Slow

Problem: Tests taking longer than expected

Solutions:

  • Check Kali VM has sufficient CPU (assign 4+ cores)
  • Check available RAM (need at least 4GB free)
  • Check network connectivity/latency
  • Monitor system resources: top (on Kali)
  • Consider running individual phases instead of full test

False Positives in Report

Problem: Findings that aren't real vulnerabilities

Solutions:

  • Review finding evidence carefully
  • Test reproduction steps manually
  • Verify HTTP request/response pairs match
  • Check CVSS justification is accurate
  • Reject false positives before reporting
